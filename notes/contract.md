# 第一项能力：执行完整的 HTTP 交互记录

## 真实使用场景

1. **SDK 版本回归**：维护者保存第三方 API 的真实响应，将已净化的 HAR
   加入仓库。测试向库中的 replay transport 发出正常 SDK 请求，断言业务结果，
   最后检查所有交互已消费。CI 不需要第三方账号、服务或令牌。
2. **连续响应**：同一请求先返回 429、随后返回 200。记录顺序模式逐次消费，
   使应用自己的重试逻辑可以验证响应序列；本库不实现重试或睡眠。
3. **请求漂移定位**：接口路径、正文或选定请求头变化时，测试得到字段差异。
   失败不消费夹具，修正请求后可以继续使用同一 session。结束检查揭示遗漏调用。

## 最小公开边界

`compile_har` 验证并编译记录，返回可复用的 Cassette；每次 `session` 生成独立
消费状态。`take` 返回已记录响应，`finish` 断言全部消费，`reset` 显式重置。
默认严格顺序；按请求查找模式必须拒绝会返回不同响应的歧义记录。
相同请求和相同响应的重复记录按原记录顺序逐个消费。

请求身份包括精确方法、绝对 URL、正文 bytes，以及调用方明确选择的请求头。
不自动排序 query、不折叠重复头、不把不同 URL 猜成等价。未命中没有联网分支。

## 输入、运行环境与保真

输入是预先净化、完整嵌入正文的 HAR 1.2。正文支持 UTF-8 文本和严格 base64
响应。请求仅支持可完整还原的 UTF-8 text；multipart、外部文件正文、升级协议、
缺失响应正文、SSE 等持续流必须拒绝。HEAD/204/304 的语义空正文单独检查。

HAR 是应用级记录，不是 wire capture。原始输入字符串完整保存在 Cassette 中；
不导出重新序列化的 HAR。影响重放的未知字段必须拒绝，记录元数据原样保留。
默认 profile 拒绝压缩、chunked 及非 UTF-8 的响应头语义，防止正文与头不一致；不偷偷
删除 Content-Encoding、Content-Length 或其他头。重复头的顺序和全部值保留。

库核心面向 wasm、wasm-gc、js、native；文件 CLI 单独声明目标。
Transport 适配同时提供 buffered send 和有限内存正文的 send_stream。
它不模拟实时分块、延迟、网络失败、取消或背压。

## 正确性约束

限制输入长度、交互数量和每条正文长度。畸形 HAR、非法 base64、正文长度冲突
及不支持的输入带 JSON 路径诊断。拒绝不能修改 session；同一输入与请求序列
产生确定结果；一个 cassette 的不同 session 不共享消费状态。状态查询和返回
响应的可变数组均不得泄漏内部存储。匹配诊断只报告字段及记录索引，不回显密钥。

## 首个演示与验收

文件 CLI 读取 HAR 和请求清单，在断网情况下输出状态和正文长度，随后检查
没有剩余交互。另以 transport 注入业务函数验证真实响应内容。真实夹具需要
注明原始来源、取得方式和许可证；构造的边界用例与真实夹具分开说明。

评估者无需基础设施即可运行所有单元测试、文件演示和 transport 演示。
实际记录采集不是默认测试的一部分。

## 后续能力

- 当前切片：完整记录导入、严格匹配、消费状态、诊断、文件及 SDK 接入。
- 已实现：显式 DecodedContent profile 适配已解码 gzip/br/deflate HAR，逐项报告头修改；不执行解压。
- 已实现：夹具更新审查，按请求身份对齐并报告响应行为变化；元数据变化不在行为报告内。
- 后续：按独立 profile 增加可完整还原的请求正文格式；保持拒绝未知语义。

录制代理、自动脱敏、OpenAPI 校验、持久工作流和通用 HTTP 客户端不在本项目边界内。

## 响应断言

Expectation 只检查显式指定的状态、完整正文和头值列表。take_checked 在所有检查
通过后才消费一次交互；状态、正文、重复头顺序或头缺失断言失败均保留原消费位置。
CLI 支持相同语义并拒绝互斥正文断言和非法 base64，不进行 schema 验证。

## 回放分支与事务

fork 从当前状态产生独立消费数组，复用不可变 cassette。transaction 在失败时恢复
完整快照，成功提交并返回回调值。内层成功、外层失败时恢复外层快照；内层失败可被
外层捕获并继续。异步版本使用 errdefer，取消后必须等结构化任务清理完成才观察恢复
结果。只回滚 session，不能撤销网络、业务数据或进程终止，期间不得并发访问父 session。

## 可复用请求计划

plan 包拥有原 CLI 的清单验证与原子执行工作流；不提供通用 HTTP 客户端或动态模板。
解析完成后计划不可变，可反复用于独立 session。默认完整消费，组合时必须显式关闭
计划级完成检查，并在外层完成检查。任何步骤与最终检查错误都恢复进入时消费状态；
错误加上步骤索引，保持原始诊断类别。CLI 失败时不输出之前步骤的成功行。

## 消费状态报告

每份报告复制当前 used 状态，仅公开按原记录顺序排列的 consumed/remaining 索引和匹配模式。
二者不相交、无重复、并集等于全部索引。之后的消费、reset、分支及事务不改变旧快照。
报告不是持久 checkpoint 或尝试日志。CLI 的 --report 在成功/失败时输出确定性 JSON；
失败报告使用原子回滚后状态，输入验证失败时状态为 null。报告诊断仅包含固定类别与路径，
不回显请求、正文及任意原始头。decoded profile 的修改审计明确保留在 adaptations 字段。

## 每个请求身份的序列

PerRequest 显式允许不同精确请求身份之间重排，只消费当前身份的最早未消费项。
同身份的不同响应不视为歧义，必须按原序逐个执行；断言不参与选择，失败不能跳过。
身份仍含完整方法/URL/正文/选定头，未选择的头不划分序列。Ordered 与 ByRequest 原行为保留。
它适合独立 API 分支的重试序列，不区分同身份并发调用，session 仍需独占使用。

## 带执行结果的验证

Plan.verify 只执行一次，与 run 共用引擎；成功提交消费，失败回滚。RunReport 保留每步
检查的 Passed/Failed/Skipped 与独立 completion，预期错误作为数据返回，意外错误继续抛出。
passed 表示整体提交，之前通过的检查不代表回滚后仍消费。默认完成检查占一个独立用例；
关闭时无该用例。输出为稳定 JSON 和常用 JUnit XML 子集，无时钟与 HTTP 值。
CLI --junit 接受新的输出文件路径，在执行前拒绝已有路径。输入失败无报告，回放失败
生成失败报告并退出 1；输出失败退出 2，不撤销已经完成的 session 操作。

## 生成可执行请求计划

Cassette.request_plan 导出一个完整的下游请求清单，保留方法、原 URL、全部有序请求头
和 UTF-8 正文字节；默认断言状态，可显式增加 base64 响应正文断言。输出不是 HAR
重写，原始记录仍保留在 source 中，decoded profile 的适配审计仍可查。生成只读、
确定且受输出上限约束；不截断或省略超限步骤。prepare 文件工作流拒绝已有输出，
只有编译和完整导出成功后才写入，摘要保留全部适配审计。

## 不改变行为的匹配解释

Session.explain 在独立 fork 上调用实际 take，报告当前结果与会消费的索引；不会执行
响应断言。候选比较所有身份字段，只保留有界的前 K 项，按差异数量、未消费、索引稳定
排序，包含已消费记录但不包含任何 HTTP 值。最近项不是可接受匹配。报告为独立快照。
计划可显式在失败点采集解释，然后按原规则整体回滚。解释中的消费与最终状态分开表达，
默认执行不增加扫描成本；原诊断、状态、响应与消费语义保持不变。

## 独立回归套件

SuiteCase 绑定安全的公开用例名、已编译 cassette、计划与匹配模式。verify_suite 在执行
前验证唯一名称和总检查预算，随后每项使用新 session；预期回放错误不阻止后续项。
报告保留原序、独立结果及全部适配审计，JSON/JUnit 确定；JUnit 的 classname 和
testcase 名称均带用例标识。原有单计划 JUnit 字节保持不变。CLI 先读入并验证所有输入，
禁止空清单、未知字段、重复 key 与超限输入；预检失败没有部分执行结果或新报告文件。

## JSON 存在性守卫

present 要求 pointer 可解析到值（包括 null），absent 要求路径不存在。数组上的非法
索引是错误，不是缺失；语法正确但超出范围的索引视为缺失。所有 JSON 检查共享 256 项
预算，配置时拒绝同一路径的存在/缺失矛盾。正文始终按严格 UTF-8、重复 key 和深度规则
验证，不能借 absence 检查绕过解析。旧的精确值断言及其错误类别保持不变。

## 指定 JSON 业务字段的夹具审查

compare 的 json_pointers 为显式 opt-in；省略时保持字节比较及原报告格式。选择后仍
比较状态和未排除的头，只将正文比较限制到列出的字段；报告记录范围和逐字段变化索引，
不输出实际值。字段缺失与 null 不同，数值 token 保真。所有输入正文都需通过严格 JSON
验证，包含未对齐项；非法选择器和空/重复/超限配置必须拒绝。整个记录新增/删除仍按
原 Change 表达，不伪造字段级对齐。原 HAR 与全部适配审计保留。
